# Расход памяти в 0.3.2

Контрольный замер на Windows 10 x64, 11 октября 2026 года. Приложение свернуто в полоску, профиль пустой, медиамост включён, активного плеера нет. Сводка при запуске, чтение уведомлений Windows, системные события и обнаружение полноэкранного окна отключены в обоих профилях. После запуска выдержано 8 секунд.

| Сборка | Сумма private memory | Сумма working set |
|---|---:|---:|
| 0.3.1, включая прежний медиамост PowerShell | 274.1 МиБ | 457.1 МиБ |
| 0.3.2, медиамост включён | 204.4 МиБ | 361.0 МиБ |

В основном сценарии private memory уменьшилась на **69.7 МиБ, примерно 25%**. Это сумма процессов Electron и вспомогательных процессов Island. Независимые stdio-серверы MCP, которые запускают Codex и Claude, в дерево Island не входят. Числа отличаются от значения одной строки диспетчера задач. Working set может учитывать общие страницы несколько раз; его сумма не означает уникальный объём физической памяти. Каждая строка — отдельный запуск, не среднее серии. Значения зависят от Windows, графического драйвера, кешей Chromium, числа задач и уведомлений; отключение модуля не гарантирует немедленное уменьшение общей памяти.

В 0.3.2:

- Системная медиасессия читается C#-мостом в существующем IslandBridge.exe. Отдельные PowerShell и консольные процессы не запускаются. Нативный мост проверяется через реальный WinRT API перед измерением.
- Полный интерфейс задач не смонтирован, когда островок свернут. Часы интерфейса обновляются только при просмотре активного таймера.
- Изменения системного состояния передаются отдельным IPC-событием, без повторной отправки всех задач и уведомлений.
- Отключение музыки, системных событий и чтения Windows-уведомлений останавливает соответствующий опрос. Иконки перечитываются только при смене приложения-источника.
- Браузерный мост, примеры задач, интерактивное демо и его стили исключаются из Windows-фронтенда во время сборки. Это проверяет scripts/check-production.mjs. Демо сайта собирается отдельно.
- Для интерфейса оставлены только латинский и кириллический наборы шрифта.

## Повторить замер

После `npm run dist`:

```powershell
node scripts/measure-memory.mjs --exe "release/win-unpacked/Windows Island.exe"
node scripts/measure-memory.mjs --exe "release/win-unpacked/Windows Island.exe" --no-media
```

Скрипт запускает готовое приложение в отдельном временном профиле, собирает дерево процессов через Windows и закрывает приложение. Личный профиль и задачи не меняются. Для сравнения с распакованной сборкой 0.3.1 используйте `--legacy-media`: её тестовый режим сам не запускает PowerShell-мост, поэтому скрипт запускает прежний мост из ресурсов той сборки и включает его в замер. Для этого нужна отдельная распакованная сборка 0.3.1, а не exe новой версии.

Electron сохраняет базовый расход Chromium и отдельный GPU-процесс. Отключать аппаратное ускорение ради меньшей цифры без проверки плавности анимаций и нагрузки CPU в этой версии не стали.

В 0.3.3 игровой оверлей выключен по умолчанию. Отдельного процесса для ресурсов нет: CPU/RAM/PDH, WMI и чтение RTSS выполняет существующий нативный мост. Когда капсула скрыта, опрос ресурсов остановлен, PDH закрыт. Значения не сохраняются в базе. Нагрузка включённого оверлея и внешних LibreHardwareMonitor/RTSS не входит в приведённый замер 0.3.2.

## Контрольный замер 0.3.4

В том же сценарии одного запуска (скрытый Island, пустой временный профиль, системный медиамост включён, 8 секунд после старта) получено **191.8 МиБ private memory** и **354.4 МиБ working set** для всего дерева процессов. Это контрольный замер, не среднее и не гарантия одинаковой цифры на другом ПК. Игровой оверлей выключен, записи нет, наблюдение буфера в тестовом профиле выключено. Существующий нативный мост добавляет только проверку номера/форматов буфера, когда пользователь включает уведомления. Запись не создаёт дополнительного процесса: медиапотоки, canvas для области и AudioContext для смешивания появляются только при записи и освобождаются после остановки. Видео отправляется на диск порциями; при отставании диска MediaRecorder приостанавливает кодирование вместо бесконечного роста очереди. Расход во время записи зависит от разрешения и источников звука и не входит в этот замер.
